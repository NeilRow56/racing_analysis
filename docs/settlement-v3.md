# Settlement v3

`canonical_settlement_v3` is the default for newly calculated research and newly settled prospective outcomes. `canonical_settlement_v2` and unversioned stored outcomes remain original evidence. An outcome's settlement version is independent of its frozen model, feature, price, cohort and collection versions.

For an ordinary £1 SP win single, decimal odds include returned stake. A winner's gross return is decimal SP divided by the dead-heat divisor; net profit is gross return minus £1. Ordinary losers and explicit started non-finishers lose £1. Returns are uncapped unless an existing, explicitly selected diagnostic or frozen capped-price rule requests a cap.

Authoritative terminal void/abandoned evidence overrides provisional finishing positions. Genuine non-runners retain their separate identity. Both receive refunds and contribute no effective settled stake, win, loss or market expectation. The research settlement helper returns `null` for these exclusions; prospective cash-refund fields may explicitly record £1 returned and £0 profit. Refunds never enter ROI stake denominators. Missing, non-final or ambiguous `other`/zero records remain unresolved; they are not inferred refunds or losses. Explicit source non-finisher codes can establish a loss without a winning time.

Positive final positions establish ordinary wins/losses; a populated unknown or non-final race stage withholds settlement. Dead-heat winners retain win status, even when their net return is negative. The existing market A/E calculation retains fractional winning credit (`1/divisor`) and uses the same complete, valid SP-covered subset for actual and expected wins. Void and winnerless unresolved fields cannot form a market book.

Historical readers annotate retained caches with identity-bound, read-only race-stage and non-finisher evidence. They never refresh cached SP, positions, features or manifest bytes. A configured database failure is surfaced. Without database evidence, ambiguous legacy results stay unresolved. Reader memoization includes settlement version and database evidence identity. Existing feature/source compatibility checks and the missing-minute Jump guard remain enforced. New cache manifests can record v3 when a future separately authorized build occurs; no cache was generated for this change.

Research Filters and backtests use v3 for new calculations. Saved v2/unversioned snapshots display their original version and a warning. Recalculations must be separate artifacts, not updates to frozen snapshots. Prospective writers tag only fresh settlements, preserve already recorded outcomes and use settlement-only projections of result evidence. Read-time monetary adapters dispatch on the recorded version; mixed ledgers retain their original money. No automatic monetary backfill is provided. The TPR/Timewise ledger likewise preserves original arithmetic for old records and versions fresh results. Two frozen feature builders explicitly retain the original classifier so settlement changes do not alter model inputs.

The implementation covers Research Filters/model comparisons, historical backtests/holdout summaries, all-family Value books, Forward Value, AW/Jump Rating and Tissue, paired/shadow Tissue, Tissue Generation, Rank One, Hurdle Recency, Jump G4, OR/Speed, Today's Rating Weight, Today rule settlement and TPR/Timewise returns. Collection, scoring, frozen rules and price-cap eligibility are unchanged.

Run `bun run scripts/validate-settlement-v3.ts data/research/settlement-v3-validation-<new-name>` for an offline replay of the six **fixed audited definitions**. It directly reads archival caches solely for regression; this does not authorize their use as compatible application sources. It checks all 80 void records, 68 dead-heat winners, 189 non-final records, original source hashes, pinned cache hashes and snapshot preservation. It records differences between current mutable prospective files and the earlier audit rather than restoring them. Cohorts are reconstructed from audit evidence, so aggregate reproduction does not establish original contemporaneous selection lineage.

## Integration remediation — 11 November 2026

`capture-pin-compatibility.ts` permits only exact reviewed original/current hash pairs for the Hurdle Market Edge and armed Early Turf feature-classifier adapters and their guard wiring. The original source bytes were recovered from Git and match the ledger pins. Adapter differences are identifier substitutions to the original v2 classifiers, with regression coverage; an additional exact Backtest dependency hash protects those classifiers. Unknown source changes, original pin changes and pin-set changes fail closed. Ledger pins and capture provenance are retained.

Hurdle V3 Shadow collection remains blocked by its semantically changed Backtest dependency. Positive/Neutral collection remains blocked by the semantically changed Tissue Generation settlement dependency. Neither semantic dependency was approved through the compatibility table. Market Edge's own guard is repaired, but fresh pairs still depend on the blocked Shadow collector. Early Turf is armed for its original March–July 2027 window. Shadow result mutation has a separate frozen-capture guard and is not source-pin blocked; the three derived monitors read outcomes from identity-matched source books. No operational collection or settlement was run for this remediation.

AW comparisons, AW/Jump Rating, Forward Value and TPR/Timewise CLI reports disclose recorded settlement versions. AW and TPR/Timewise render separate version tables; Rating reports partition their cohorts; Forward Value exposes separate retained monetary totals and family tables and explicitly identifies any combined recorded views. Unversioned evidence remains distinct from explicit v2. Corrected historical recalculations are separate artifacts, never relabelled old money.

The three standalone transfer/robustness diagnostics use canonical V3 settlement for monetary arithmetic and exclusions. Slippage applies to canonical gross returns, including dead-heat division. Corrected file outputs use new `-settlement-v3` paths and version labels; historical reports were not regenerated.
